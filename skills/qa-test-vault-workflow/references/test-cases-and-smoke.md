# 测试用例与冒烟用例标准

## 一、测试用例

### 1. 生成门禁

只在用户明确发出"生成测试用例"后执行。测试点完成不等于授权；"继续"也不等于授权。

### 2. 文件结构

```
frontmatter（release / req-id / module / type: test-cases / tags）
# 测试用例——{需求名}
> 依据：需求.md + 测试点.md + 确认日期
## 1. 任务理解（本期范围、已确认口径、明确不做）
## 2. 覆盖策略（优先级分层、维度、高风险区、多端、总量）
## 3. 用例
### {端}
#### {模块}（PRD x.x）
| 编号 | 前置条件 | 操作步骤 | 预期结果 | 优先级 | 关联 | 执行结果 |
## 非功能与其他
```

"任务理解"不是套话：写清本期范围、A 类确认结果、排除项，后续用例才有边界。

### 3. 表格写法

| 列 | 要求 |
|---|---|
| 编号 | `TC-{NN}`，同文件内递增；删除不重排 |
| 前置条件 | 账号/角色/数据/状态；跨账号场景写清两个账号分别是谁 |
| 操作步骤 | 编号 1. 2. 3.，用界面上可见的按钮、页面、字段名；一条用例只走一条路径 |
| 预期结果 | 与步骤一一对应；写可观察的界面结果、提示文案、状态变化、接口返回 |
| 优先级 | P0 主流程与红线；P1 重要异常/辅助；P2 兼容/非功能 |
| 关联 | `TP-A01-03` / `PRD §4.2` / `AC-05`，至少一项 |
| 执行结果 | 通过 / 失败 / 部分通过 / 阻塞 / 未执行 |

多步内容用 `<br>` 分行，不要把三步塞进一格用逗号连写。

### 4. 覆盖面

- 每个 P0 模块至少：1 条正向主链路、1 条异常、1 条边界（适用时）。
- 高风险区加深：合规红线、权限、状态流转、跨端同步、金额/数量计算。
- 跨端：同一条业务至少有一端发起 + 另一端确认的闭环；数据回写要单独断言。
- 非功能：性能指标按 PRD 非功能表逐条；兼容按端与版本；安全覆盖越权、敏感信息、软删除。
- 变更驱动：只覆盖新需求 + 受影响模块；存量靠主流程回归兜底，不做全量重跑。
- 总量由用户口径决定（常见 80–120 条）；不要为凑数写重复用例，也不要为省事合并不同断言。

### 5. 修订联动

测试点修订后：先更新用例，再在汇报里列"受影响 TC 编号 + 失效原因"。不允许只改测试点、不改用例。

### 6. 汇报

```
测试用例.md 已生成/更新：N 个模块，M 条（P0 x / P1 y / P2 z）。
覆盖：正向 / 异常 / 边界 / 跨端 / 非功能。
与测试点差异：…
等候指令：生成冒烟用例 / 转 xmind。
```

## 二、冒烟测试用例

### 1. 定位

冒烟文件不是 `测试用例.md` 的子集或精简版，而是**独立的端到端主流程验证文件**，用于提测/上线前的准入。

### 2. 八条标准

1. **触发**：只在用户明确发出"生成冒烟用例"后生成，不随测试点或全量用例自动生成。
2. **覆盖目标**：用最少用例覆盖全部正向 P0 主链路；不覆盖单功能点、边界异常、弱网、非功能。
3. **用例形态**：每条是完整端到端流程，多步操作 + 多步预期，不是单按钮验证。
4. **多端组织**：优先按"归属方 → 接收方 → 数据回写"或"发起端 → 消费端 → 反向确认"写成一条；不拆成两端各自的功能清单。
5. **优先级**：默认全部 P0；若某条不是核心链路，必须单独说明理由。
6. **编号**：`TC-S-{NN}` 为默认；历史文件用 `SMT-{NNN}` 时沿用该文件体系，同一需求不混用。
7. **关联**：每条引用覆盖的 TP 编号或 PRD 章节，便于需求变更时定位。
8. **格式**：与测试用例表一致，列：编号 / 流程名称 / 前置条件 / 操作步骤 / 预期结果 / 优先级 / 关联 / 执行结果。

### 3. 文件结构

```
frontmatter（type: smoke-test-cases）
# 冒烟测试用例——{需求名}
> 依据 + 范围
## 1. 任务理解
## 2. 冒烟策略（执行顺序、准出标准、预计耗时）
## 公共前置（账号 / 角色 / 数据）
## 正向主流程
| 编号 | 流程名称 | 前置条件 | 操作步骤 | 预期结果 | 优先级 | 关联 | 执行结果 |
```

准出标准必须可判定，例如"全部通过；任一失败阻断提测/上线，修复后重跑失败项及关联链路"。

### 4. 汇报

```
冒烟测试用例.md 已生成：N 条端到端流程，覆盖 A/B/C 三个主链路。
准出标准：全通过。
等候指令：转 xmind。
```

## 三、常见错误

- 用例只有预期没有前置，执行时无法造数。
- 步骤写"进入页面操作相关功能"，执行人无法复现。
- 预期写"显示正常"，无法判定通过。
- 冒烟用例写成功能点清单，失去端到端价值。
- 用例总数越写越多，覆盖却没有增加——先看维度，再看条数。
